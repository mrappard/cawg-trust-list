== CAWG trust list

=== Relationship to the CAWG trust configuration

The CAWG Trust List populates the existing CAWG trust configuration. It does not define a new trust mechanism. For the `id-kp-documentSigning` EKU:

* the list of accepted certificate policies MUST include the CAWG certificate policy OID; and
* the list of trust anchors MUST include the trust anchor configurations in the current CAWG Trust List.

[NOTE]
.Design choice: certificate policy rather than a new EKU
====
The C2PA distinguishes its signers with a dedicated EKU (`c2pa-kp-claimSigning`, 1.3.6.1.4.1.62558.2.1).
The CAWG trust configuration already pairs each EKU with a list of accepted certificate policies, and already requires `id-kp-documentSigning`.
This proposal therefore identifies CAWG member certificates by a CAWG certificate policy OID under `id-kp-documentSigning`, which needs no change to the identity assertion's trust configuration structure.
A dedicated CAWG EKU remains an alternative; see <<_open_questions>>.
====

=== Trust anchor configurations

Each entry in the CAWG Trust List is a trust anchor configuration, as in the C2PA technical specification:

* The configuration MUST include the X.509 certificate for the trust anchor.
* The configuration SHOULD include a `notBefore` date/time, before which there is no trust for that configuration.
* If trust in the configuration has ended, the configuration SHOULD include a `notAfter` date/time, after which there is no trust for that configuration.

If a `notBefore` date/time is present, the configuration MUST NOT be used for identity assertion signatures whose time stamp (or current time, if no time stamp is present) is before that date/time.
If a `notAfter` date/time is present, the configuration MUST NOT be used for identity assertion signatures whose time stamp (or current time, if no time stamp is present) is after that date/time.

NOTE: Removing a participating CA is done by setting `notAfter`, not by deleting its entry, so that identity assertions time-stamped while the CA was trusted remain valid.

=== Validator behaviour

A validator that uses the CAWG Trust List:

* MUST include the CAWG Trust List in its default CAWG trust configuration;
* MUST accept a `cawg.x509.cose` signer certificate as chaining to the CAWG Trust List only if the certificate contains the `id-kp-documentSigning` EKU, contains the CAWG certificate policy OID, and has a valid chain to a trust anchor configuration in the list that is in effect at the time of signing;
* MUST use only the trust anchors that the CAWG trust configuration associates with EKUs present in the signer certificate;
* SHOULD allow users to configure additional trust anchors and to opt in to lists maintained by other parties; and
* SHOULD refresh its copy of the CAWG Trust List periodically.

Validation outcomes use the existing identity assertion status codes, such as `cawg.x509.credential.trusted` and `cawg.x509.credential.untrusted`. This proposal does not define new status codes.

=== Publication format

The list operator MUST publish the CAWG Trust List at a stable HTTPS URL in at least the following forms:

* a PEM bundle of trust anchor certificates, for compatibility with existing tooling (as done by the C2PA and the IPTC); and
* a machine-readable document that also carries each configuration's `notBefore`/`notAfter` dates, a list version and a publication date.

The machine-readable document SHOULD be signed by the list operator.

The following is an illustrative, non-normative example of the machine-readable form. The exact format is an open question.

[source,json]
----
{
  "listVersion": 3,
  "published": "2027-01-15T00:00:00Z",
  "eku": "1.3.6.1.5.5.7.3.36",
  "certificatePolicies": ["<CAWG certificate policy OID>"],
  "trustAnchors": [
    {
      "name": "Northwind Traders CAWG Issuing Root",
      "certificate": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----",
      "notBefore": "2026-12-01T00:00:00Z"
    },
    {
      "name": "Fabrikam Identity Root 2026",
      "certificate": "-----BEGIN CERTIFICATE-----\n...\n-----END CERTIFICATE-----",
      "notBefore": "2026-12-01T00:00:00Z",
      "notAfter": "2028-06-30T23:59:59Z"
    }
  ]
}
----

=== Time stamping and private credential storage

The CAWG identity assertion specification already states that its requirements for Time Stamping Authorities and private credential storage are identical to those in the C2PA technical specification. The CAWG Trust List does not change this: validators continue to use the C2PA TSA Trust List for time stamps.
